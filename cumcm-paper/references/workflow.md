## 1. 端到端 12 步与阶段门

12 步：赛题解析 → 交付物/评分点拆解 → 数据与约束审计 → 最低可行基线 → 候选模型 → 预先设计测试 → 最小纵向切片 → 批量实验 → 消融/灵敏度/稳健性 → 图表与解释 → 论文同步写作 → 红队与复现。

- 阶段门决定「继续 / 回退 / 换路线」，一轮结束看是否得到**可判定证据**，不靠时长。
- 每个主张内部跑小闭环：判据 → 实现 → V&V → 证据 → 主张。
- 新证据触发上游修订；契约变更记录原因并标明哪些旧结果要重算（冻结=控变更，发现错仍要改）。

## 2. 四份最小契约 + 工件 ID

- **problem**：决策问题、范围、变量、单位、假设、硬约束、必答项；
- **data**：来源、字段、缺失/异常规则、时序/分组结构、划分策略（原始数据只读）；
- **model_api**：输入输出、前后置条件、不变量、错误行为；
- **evaluation**：基线、指标方向、容差、计算预算、揭盲规则、接受/否决条件。

工件稳定 ID（文件名、日志、图题、账本一致，零填充版本号）：
`Q`问题 `D`数据 `M`模型 `EXP`实验 `C`主张 `FIG`图 `TAB`表。例：`fig_q2_robust_v03.pdf`、`exp_q2_m03_seed42.yaml`；禁止「最终版/真的最终版」。

## 3. 最小纵向切片与证据链

- 先打通一条可验证主线：少量数据 + 一个基线 + 一个指标 + 一张图 + 一段解释，链路为
  source → definition → assumption → equation → 验收判据 → algorithm → V&V → evidence → answer → paper claim；
  通过后再横向扩到全量数据、高级模型、参数搜索、多指标、多情景（复用同一契约/测试/证据接口）。
- **证据链反向可审计**：论文主张 ← 图表 ← 实验记录 ← 配置/运行命令 ← 代码版本 ← 模型定义 ← 原始数据。任一环节缺失即证据不足、不进论文。
- 每次正式实验登记：实验 ID、待验证主张、预设支持/否决条件、数据版本与哈希、代码/模型/配置版本、随机种子与命令、输出指标、残差/裕度/区间、图表、结论状态（支持/不支持/证据不足/失败，失败也留）。
- **写作只读已生成工件，不在改文字时重算或手改数值**；模型契约一变，相关 claim 标失效并重跑。同步报「EXP-017 用 M-03、D-02、种子42，指标 0.812→0.846，扰动>15% 下降，图见…」，不报「效果还行」。

## 4. 九字段交互协议与指引词

给 AI 下任务用九字段：角色 / 任务目标(唯一可判定) / 已知输入(版本) / 不可修改约束 / 执行步骤 / 输出工件 / 验收标准(阈值) / 禁止行为 / 失败回退。返回四态之一：完成给工件｜材料不足列缺口｜测试失败给回退｜约束冲突请人决策；不为「显得有帮助」降低验收标准。

指引词（一词触发一组动作，带作用域与版本）：
- 澄清/重述/拆解/依赖/分支/收敛；
- 基线/量纲/极限/守恒/反例/消融/灵敏度/稳健性/证伪/泄漏；
- 红队/审计/压缩/移交/对齐/冻结/合并；
- 图证/降噪/模仿/评审/复现。
- 「模仿」只迁移论证动作与信息顺序，不复制句子、模型名、数据；验证从便宜强筛错的检查（量纲/极限/守恒）开始，再做消融/灵敏度。

## 5. 72h 赛程节奏（按开赛时刻平移，预留最后 3–5h 只做排版终检）

- **第 1 天上午(0–4h)**：独立读题与附件→集中比对定题；冻结当届规则卡（页数/匿名/附件/引用/AI/文件名/提交方式）。
- **第 1 天下午**：交付矩阵、数据审计、假设清单、**最低基线先跑通**；搭论文骨架（重述/假设/符号占位，重述当天先写完）。
- **第 1 天晚–第 2 天**：按纵向切片逐问建模求解，出结果与图，CEWL 同步成文。
- **第 2 天晚**：各问都有初步结果，主干模型/评价协议冻结。
- **第 3 天上午**：灵敏度/稳健性/误差、补检验、可视化定稿。
- **第 3 天下午**：全文贯通、**精写摘要**、模型评价、参考文献、附录代码整理、AI 声明与详情。
- **第 3 天晚(截止前 3–5h)**：红队审查 → 关键数值独立复算 → 干净环境复跑 → 编译 PDF 逐页检查 → 打包；**绝不临时大改模型**；来不及就保留已验证简单模型与保守结论，舍弃未审计的复杂结果。

后期完整顺序：冻结模型→复算关键值→清理无效图表→统一变量单位→检查图表引用→核对结论范围→完成 AI 说明→待审候选→红队关闭问题→干净环境复现→冻结提交。

## 6. 三人分工与项目目录

- 不僵化「建模/编程/写作」三段互不往来；设三类主责：**问题与模型 / 计算与实验 / 证据与写作**，关键工件交叉审核（模型负责人查代码可实现性，计算负责人查图表追溯，写作负责人查数学含义）。
- 共享工件而非共享全部聊天；项目文件当前版本是唯一事实源；论文手必须完全理解模型并与建模手高频交流。
- 推荐目录：
```
00_charter/ 规则卡、MasterBrief、边界      01_problem/ 问题契约、交付矩阵、符号
02_models/ 假设卡、模型卡、候选路线        03_data/ 只读原始数据、清洗、字典、哈希
04_src/ 正式实现                          05_tests/ 单元/性质/数值测试
06_experiments/ 配置、运行记录、指标       07_figures/ 图源、脚本、矢量图
08_paper/ LaTeX、文献、提交PDF            09_logs/ 10_ai_usage/ 决策与AI日志
```
- 会话移交用启动包（目标/已确认事实/冻结决策/输入路径/输出工件/验收/禁止项/未解问题）与结束包（完成内容/结论证据/生成工件版本/被否方案/下一步）。
